# AI Film Studio

## Product vision
Convert a user's written story into a 3D animated film using existing AI
models, reusable tools, and Blender. Do not train foundation models or use
AI video generation.

## Core principle
LLMs PLAN. Validated JSON DESCRIBES. Blender EXECUTES.
Never execute arbitrary code generated by an LLM.

## Production pipeline
story -> screenplay -> shot_list -> asset_resolution -> scene_build
-> animatic -> human_approval -> final_render -> edit -> final_film

## Technology stack
- Frontend: React, TypeScript, Vite
- Backend: Python, FastAPI, Pydantic
- Database: PostgreSQL
- Background jobs: Redis and arq
- 3D animation and rendering: Blender Python API (bpy)
- Video assembly: FFmpeg
- Local development: Windows 11, PowerShell, Docker Desktop, WSL 2

## Blender configuration
Executable:
C:\Program Files\Blender Foundation\Blender 5.2\blender.exe

Use this path through configuration rather than hardcoding it throughout
the application. Allow the path to be overridden.

Production Blender scripts must support headless execution.
Scripts must consume validated SceneSpec JSON files and must not make
network calls.

## Architecture
- apps/web: film studio dashboard
- apps/api: API, schemas, database access
- workers: production and rendering jobs
- blender/scripts: deterministic scene-building scripts
- blender/templates: reusable Blender project templates
- assets: approved, reusable 3D assets
- schemas: versioned JSON contracts
- storage/projects: generated project files and render outputs
- .claude/skills: reusable development and filmmaking workflows
- .claude/agents: focused development subagents
- .claude/commands: repeatable project workflows

## Engineering rules
- Inspect existing files before changing them.
- Do not overwrite user files without approval.
- Work in small, testable milestones.
- Validate all LLM outputs with Pydantic models.
- Keep LLM planning separate from Blender execution.
- Never invent asset paths; use an asset manifest.
- Make scene-building operations repeatable and log failures.
- Add tests for schemas and core production logic.
- Keep API keys in environment variables; never commit secrets.
- Do not install dependencies or MCP servers without reviewing the plan.
- Ask before destructive operations or major architectural changes.
- Report commands run, tests passed, and known limitations.

## First milestone
Generate a simple 3D animated scene using Blender, render it, and export
a playable MP4 using FFmpeg.

Begin with procedural geometry and simple materials. Keep rendering
resolution low to accommodate the development laptop.

## Working approach
Before implementing a milestone:
1. Inspect the repository and available tools.
2. Explain the intended changes.
3. Implement only the approved milestone.
4. Run relevant tests and verify outputs.
5. Summarize files changed and remaining work.
